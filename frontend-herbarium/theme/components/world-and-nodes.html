World & nodes

The world is the map of your garden, drawn once and kept. Every plant, shelf and windowsill is a node on it, and one node at a time is the place you are standing.

Stable v1.0.0

Overview

PlantPal does not move you between screens. It keeps one world on the surface and moves the camera across it, so the answer to “where am I?” is always in view rather than in memory. A node is a place in that world — a plant, a room, a shelf — and an edge is a route between two nodes that is drawn before you take it.

Use the world whenever a view has more than one place in it and the relationships between those places matter: my garden, recent scans, the rooms a plant has lived in. Do not use it for a single sheet with no neighbours — that is a sheet on its own. Do not use it for a linear list of settings; leaving to settings is an exit, documented on Edges.

The world only ever holds one focal node. That rule is not a style preference — it is what makes the marker meaningful. See the six principles for why the map is persistent, and Traversal for how a whole journey is composed from these parts.

Anatomy of a world

A world is a frame, a canvas that pans and scales inside it, the nodes placed on the canvas by persisted coordinates, the edges between them, the you-are-here marker, and the minimap that survives every zoom level. Select a node, or press the arrow keys, and the camera travels along the edge to it.

Coordinates are persisted, never invented

Every node carries data-hbm-x and data-hbm-y as percentages of the frame, and repeats them as the inline --hbm-node-x / --hbm-node-y custom properties so the node is in the right place before any script runs. Use the same coordinates every time you draw the same graph. Two loads of my garden must lay out identically, because a map you have to re-learn on every visit is not a map.

Neighbours are declared, not derived from what happens to be nearby: data-hbm-neighbours is a comma-separated list of node ids, and it is the list the keyboard walks and the degree count reports.

The marker and the minimap

The marker sits on the canvas and travels with the camera; the minimap sits outside the canvas so it stays the same size at every zoom level. Include both. A breadcrumb on its own is not enough — you should be able to answer “where am I?” by looking, not by reading.

Node states

A node's state is drawn on the node itself. There is no page-level banner for any of these, because a problem in one corner of the world must not repaint the whole world.

ClassMeansUse it when
hbm-node--focus The one place you are standing. Always exactly one per world. Applied by the system on selection; never author two.
hbm-node--neighbour One hop from the focus. Applied by the system from the focal node's neighbour list. Do not hand-set it.
hbm-node--unknown Not loaded yet. The hatch says “we have not looked here”. A region of the garden you have not fetched. Never for a place that is genuinely empty.
hbm-node--stale Loaded, but the numbers are older than now. Offline, or a count you have not refreshed. Pair it with hbm-stale-note saying how old.
hbm-node--error This node failed to load. Together with an hbm-node-error body carrying the retry, in place.

Behaviour

Selecting a node

Selecting a node moves the camera, not the node. The canvas pans so the new focus is centred, the marker travels to it, the minimap dot travels with it, and the drawn degree of every node is recalculated from its real neighbour list. Nothing is unmounted and rebuilt, so the plant you were looking at is still in the same place when you come back.

A node never mutates anything. If a place needs an action — water, rename, remove — that action belongs on the sheet the node opens into, drawn as an action.

Zoom

Zoom rescales the same world; it never routes you somewhere else. Any control inside the world carrying data-hbm-zoom multiplies the current scale by its value, clamped so the world can never be lost off the edge of its frame.

<button type="button" class="hbm-act hbm-act--quiet hbm-act--sm" data-hbm-zoom="1.25">Zoom in</button>
<button type="button" class="hbm-act hbm-act--quiet hbm-act--sm" data-hbm-zoom="0.8">Zoom out</button>

The minimap stays the same size at every scale, so it remains the thing you can trust when the canvas is zoomed past the edges of the frame.

Keyboard

Arrow keys walk the graph, not the document. From the focal node, Right or Down moves to the next declared neighbour and Left or Up to the previous, wrapping around the list. Enter or Space makes the node under the cursor the new focus and travels the camera to it. Only the focal node and its neighbours are in the tab order, so Tab never lands somewhere you cannot see.

Reduced motion

Under prefers-reduced-motion every travel duration collapses, but nothing becomes an abrupt swap: the camera still moves to the focus, the marker still ends at the right place, and the active edge is still drawn. Direction is information, so it survives; only the time it takes is removed. Do not add your own animation on top — the world already has the only movement it is allowed.

Accessibility

Each node is given role="link", because selecting it takes you somewhere rather than changing anything. The focal node carries aria-current="true" and every other node aria-current="false", so a screen reader announces which place you are standing in without needing the marker.

Roving tab order keeps the world to one tab stop: the focus and its neighbours are reachable with Tab, everything else is removed from the order until you travel to it. This mirrors how the map works visually — you can only step to somewhere you can already see an edge to.

The marker and the minimap are decorative duplicates of information already in the node's aria-current state, so they are not announced twice. State that is not carried by colour alone: unknown regions are dashed and hatched as well as dimmed, stale nodes carry a written hbm-stale-note, and a failed node carries its message as text.

Node borders and the focus ring meet contrast at every zoom level, because zoom scales the canvas and not the rule weights. If a node needs a label that is not visible in the frame — a room name shortened to fit — add the full name with hbm-visually-hidden rather than relying on a title attribute.

Check before you ship

A world with two focal nodes reads to a screen reader as two current locations, which is worse than none. Assert one hbm-node--focus per world in your tests.

Usage guidance

Do
Balcony 3 linked

Draw a route to a neighbouring place as an edge, so its direction and its degree are readable before you commit to taking it.

Don't

Dress a place you can travel to as an action — the user cannot tell whether pressing it will move them or change their garden.

Do
Your hallway plants have not loaded yet

Say that a region is unknown when you have not looked at it, so the map never claims more than it knows.

Don't

No plants in your hallway

Report a region you have not fetched as empty — the user will believe their plants are gone.

Rules

Use exactly one hbm-node--focus per world, and move it only in response to something the user did. The camera is theirs; a background refresh may not steal it.

Give a node the same coordinates every time it is drawn. If a node's position comes from a layout run at render time, the map changes shape between visits and stops being learnable.

Update a count, a health leaf or a photo in place. A non-structural change moves nothing on the map, because motion in this system means travel and travel means the user went somewhere.

Keep the world mounted. Zoom it, pan it, and let the focused node's body scroll — but never replace the world with another screen. If a place genuinely leaves the map, say so on Uncertainty's terms rather than by deleting it silently.
