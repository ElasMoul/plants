Edges

An edge is a connection you can see before you take it. Every move between two places in your garden is drawn as a ruled line with a direction, so you know where a tap will put you without tapping it.

Stable v1.0.0

Overview

PlantPal is a place you walk around, not a stack of screens. An edge is how you walk: a rule under a name, an arrow showing which way it goes, and a destination that already exists. Taking an edge moves you. It never waters a plant, never files a scan, never changes anything you would want back.

Use an edge whenever a tap ends with you somewhere else — a plant, a bed, a scan, your care log. Use it for every neighbour a place has, and draw all of them, including the ones you have not visited.

Do not use an edge for anything that changes your garden. A change is an action, and actions are filled and stake-shaped so the two can never be confused — see Actions. Do not put an edge inside a settings drawer either: a drawer is a place you have already stepped out to, and travelling from inside it leaves you unable to say where you are. Longer journeys — several hops, going back, permission to enter — belong to Traversal.

Rule of thumb

If you can undo it, it is an action. If it puts you somewhere, it is an edge.

The plain edge

A plain edge is one named destination with the rule drawn under it and the arrow at its end. It is the form to reach for inside prose, inside a sheet footer, and anywhere a single onward step is offered.

Name the place, not the movement. Monstera is a destination; view plant details is a caption for a button that does not exist here.

The origin edge

The way back is a real edge to a real place, drawn with its arrow reversed and leading. It points at where you came from by name, so returning is one visible hop rather than a guess about history.

The edge row

When a place has several neighbours, draw them as a list of full-width rows. Each row carries a mount rule on its leading side — the edge itself — the destination's name, and its degree: how many neighbours it has. The degree is the real count, so a row promises exactly what is behind it.

A neighbour you have not loaded

When the count on the far side of an edge has not arrived yet, say so. An unknown region is drawn hatched and dashed, and it reads as not fetched rather than nothing there. The two are different facts and the interface must not blur them.

Edge tokens

An edge draws itself from two semantic colour roles and the geometry scale. Never restyle an edge on a page; change the role if the meaning changed, and otherwise leave it alone.

TokenRoleWhere it lands
--hbm-edge A drawn, traversable connection at rest. The rule under .hbm-nav; the leading rule on .hbm-edge-row.
--hbm-edge-active The edge you are on, or about to take. Hover and travel state of both forms.
--hbm-rule-hair The thin rule of a plain edge. Border width under .hbm-nav.
--hbm-rule-strong The mount rule of a row edge. Leading border width of .hbm-edge-row.
--hbm-motion-state The settle of colour and arrow on hover. Transitions on both forms.
--hbm-motion-travel The distance crossed when an edge is taken. Camera and marker travel in World & nodes.

Arrivals

When something finishes somewhere other than where you are standing, it arrives as a toast on the rail: what happened, which place it happened in, and — when the change can be taken back — the way to take it back. An arrival tells you the distance it crossed; it never pulls you along with it.

In the product, raise arrivals through the system rather than writing the rail yourself. system.js creates and owns .hbm-toast-rail:

herbarium.toast("Watered Fern", { tone: "positive", origin: "Balcony", actionLabel: "Undo" });

Callouts

A callout is a note attached to the place you are already standing in — a tip, a caution, a harm, or an admission that the system is unsure. It stays inside the flow. It is not an edge and never carries you anywhere; when a note needs a destination, put a plain edge inside it.

Reach for the unsure tone freely. Saying plainly that a diagnosis is uncertain is the honest answer, and Uncertainty covers how far to take it.

Behaviour

Rest. The rule is drawn in the resting edge colour and the arrow sits at the trailing end of the label. Nothing is hidden until hover; the connection is visible on a phone that has no pointer at all.

Hover. The rule and the arrow take the active edge colour and the arrow moves one step in its own direction. That step is the promise of the journey, and it settles at state duration.

Focus. Both forms are real links, so the system's focus ring lands on them without any extra markup. An edge row takes focus as a whole row, not as its label.

Keyboard. Tab reaches every edge in reading order and Enter takes it. Edge rows are ordinary links in a list, so nothing traps focus and nothing needs arrow-key handling.

Taking the edge. The destination is already in the world; travelling scales and pans the camera to it over the travel duration, and your marker moves with you. Nothing fades out and nothing is replaced.

Reduced motion. Under prefers-reduced-motion the duration scale collapses, so the arrow's step and the camera's travel resolve immediately. Every drawn thing stays drawn — the rule, the arrow, the marker, the degree. Direction is information here, not decoration, so it is never the thing that is removed.

Accessibility

Contrast. The label of an edge is primary text on the sheet or mount behind it, and the degree is muted text, both of which meet contrast at their sizes in paper and dusk. The rule itself is a border, not a carrier of meaning on its own: the name and the arrow say where the edge goes, so the connection survives if colour is lost entirely.

Semantics. An edge that goes somewhere is an <a> with an href. Never a <div> with a click handler, and never a <button> — buttons announce as buttons, and a screen-reader user would be told a change was about to happen when nothing changes but their position. A group of edge rows belongs in a list or a <nav> with an accessible name, so it can be jumped to and skipped.

Announcement. The link name must carry the destination and its degree together, because the degree is part of what the row promises. Read aloud, "Kitchen windowsill, 4 plants" is a complete offer. Keep the arrow out of the accessible name: it is a CSS ::after and is never announced, which is exactly right.

Origin edges. Because an origin edge names its place, its announcement is already unambiguous — "My garden, link". A generic "Back" would leave a screen-reader user with the same question the visual design refuses to leave a sighted user with.

Arrivals. A toast is content arriving without focus moving, so put it in a live region and let it announce itself. Focus stays where the user left it. If an arrival carries an Undo, give the user enough time to reach it by keyboard before the toast leaves.

Hidden context. When a row's visible text is short, add the rest for screen readers with .hbm-visually-hidden rather than an attribute that overwrites the visible label:

<a class="hbm-edge-row" href="#main">
  <span class="hbm-edge-row__label">Balcony</span>
  <span class="hbm-edge-row__degree">7<span class="hbm-visually-hidden"> plants</span></span>
</a>

Usage guidance

Use an edge for every move and only for moves. Draw all of a place's neighbours, name each one, and let the component draw its own direction.

Do
Balcony

Draw the destination as an edge and the change as a filled action, so the two are told apart by shape before either is touched.

Don't

Give a place and a change the same filled form — nothing on screen says which one alters your garden.

Do
My garden

Name the place an origin edge returns to, so going back is a step to somewhere rather than a step into history.

Don't
Go back <-

Label an edge with a direction and type an arrow into it — the component already draws direction, and it flips it for right-to-left readers.

Before you ship an edge

Check the degree is the real count, that every neighbour is drawn, and that nothing on the other side of the edge changes just because you took it.
