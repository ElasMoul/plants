RTL & locale

PlantPal is used in Arabic, Hebrew, Persian and Urdu as well as in English. Every component here already mirrors itself; this page tells you what the system does for you, and the four things you still have to get right.

Stable v1.0.0

Overview

Set dir on the document from the user's locale and the whole system flips: the mount margin of a sheet moves to the right, edge rows grow their rule on the right, the direction arrow on an edge points left, and the care log's timeline runs down the right-hand side. You do not write a mirrored stylesheet, and there is no RTL build.

This works because system.css is written in logical properties. A rule says border-inline-start, not border-left — the browser resolves “start” against the current writing direction. Use this page when you are adding page-scoped CSS, positioning something by coordinate, or writing a sentence that mentions a direction.

Do not use this page to decide what to say in another language. Wording lives in Voice & copy; the six principles it serves are in PRINCIPLES.md.

Direction is set once, on an ancestor

Set dir="rtl" on <html> for a right-to-left locale. Set it on a smaller element only to show both directions side by side, as this page does. Never set it on a single component to “fix” alignment — that misdirects everything nested inside it.

Write logical properties, never physical ones

Every physical property has a logical twin that means the same thing relative to the reading direction. Use the twin. A physical property is the single most common way a page breaks in Arabic, and it breaks silently — the layout still renders, it just faces the wrong way.

Never writeWrite insteadWhy
margin-left / margin-right margin-inline-start / margin-inline-end Spacing that leads the text should follow the text.
padding-left / padding-right padding-inline-start / padding-inline-end Indents belong on the reading side.
border-left / border-right border-inline-start / border-inline-end The mount rule of a sheet is a start edge, not a left edge.
top / left inset-block-start / inset-inline-start Absolute placement must mirror too, or a badge lands off its corner.
text-align: left text-align: start Body copy aligns to where the line begins.
float: right float: inline-end The trailing side is a direction, not a hand.
a four-value border-radius in physical order border-start-start-radius and friends The plant tag's punched corner has to stay on the hanging side.

Two things are not mirrored and must not be: the --hbm-space-*, --hbm-radius-* and --hbm-dur-* scales are direction-neutral, and so are the values you pass them to. Reach for a logical property; keep the same token.

/* Correct: logical property, scale value, no direction baked in. */
.my-page-diagram { padding-inline-start: var(--hbm-space-5); }

What the components already mirror

You do not need to intervene in any of this. If a demo of yours seems to need one of these undone, the demo is wrong.

ComponentBehaviour under dir="rtl"
.hbm-nav The direction arrow becomes a left-pointing arrow, and its hover travel reverses with it.
.hbm-edge-row The traversal rule moves to the right-hand side; the degree count follows the label.
.hbm-sheet--mounted The mount margin moves to the right-hand side.
.hbm-log__entry The diary spine and its dots run down the right-hand side.
.hbm-switch The thumb travels leftward when checked, so “on” is still forward.
.hbm-node, .hbm-marker Placement resolves from the inline start, so the whole world mirrors as one picture.
.hbm-toast-rail, .hbm-menu, .hbm-worldview Anchored to the inline edge, so arrivals and menus appear on the reading side.

Direction lives in the component, never in your prose

Never write “tap the arrow on the left” or “swipe right to water”. In Arabic that instruction is false, and no translator can repair it without knowing your layout. Name the thing instead: “open your garden”, “choose Log watering”.

The same applies to a typed arrow. Never put &rarr; in a string. An edge draws its own arrow and flips it; a hand-typed one does not.

Text that names a plant sits inside the sentence direction, so a Latin binomial inside Arabic copy still reads correctly — it is marked with .hbm-binomial, and the browser's bidirectional algorithm handles the rest. A binomial is never something the user has to type. This is the same rule the Uncertainty pattern relies on when it hedges an identification.

Numbers, dates and names of plants

PlantPal shows a lot of small quantities: a neighbour count on an edge, a plate number, “due today”, “watered 3 days ago”. Format all of them with the user's locale rather than by concatenating a number and a word — several locales use their own digits, and every locale orders a date differently.

new Intl.NumberFormat(locale).format(count);
new Intl.DateTimeFormat(locale, { day: "numeric", month: "long" }).format(when);
new Intl.RelativeTimeFormat(locale, { numeric: "auto" }).format(-3, "day");

A nickname is whatever the user typed and is never transliterated or corrected. Plant names shown by the system are translated where a common name exists in the locale, and fall back to the binomial where one does not — the fallback is visible, not silent. Related counts and due-date rules live on Due today.

Accessibility

A mirrored layout is only correct if what a screen reader hears mirrors with it.

  • Declare the language. Set lang alongside dir on <html>, and set lang on any run of text in a different language. A screen reader picks its voice from lang, not from the characters.
  • DOM order is reading order. Never reorder with flex-direction: row-reverse or a grid order to fake a mirror — the visual order flips but the tab order and the announced order do not, so keyboard focus jumps around the screen.
  • Keyboard arrows follow the visual direction. Where a component moves selection with the left and right arrow keys, the left key moves toward the visual left in both directions. In RTL that is forward through the list.
  • Contrast is unchanged. Mirroring does not alter colour, so every combination that passes in paper and dusk still passes; check any page-scoped CSS you added in both themes.
  • Announce the state, not the side. A visually hidden label reads “needs attention”, never “marker on the right”. Use .hbm-visually-hidden for it.
  • Test with the keyboard in RTL. Set dir="rtl" on the document and tab through the whole page; focus should travel from the right edge leftward, in the order the content reads.

Usage guidance

Do
حديقتي

Let the edge draw its own direction arrow, so it points the way the reader is going in every locale.

Don't
→ حديقتي

Type an arrow into a string — it keeps pointing right while the whole layout has turned around it.

Do

Name the action in the label, so the instruction survives translation without a diagram.

Don't

Point at a position instead of naming the thing — the left side is not where the button is any more.

Before you ship a page

Set dir="rtl" on <html> and read the page top to bottom in both themes. Anything that stayed on the left is a physical property you have not converted yet.
