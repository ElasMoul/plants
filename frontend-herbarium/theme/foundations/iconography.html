Iconography

Herbarium ships no icon set. What looks like an icon in PlantPal is a drawn mark that a component owns — a leaf, three rungs, a dot, a ring around a leaf spot — and every one of them is read aloud as text.

Stable v1.0.0

Overview

You will not find a pictogram font, an SVG sprite or an hbm-icon class in this system, and you must not add one. PlantPal is a paper register, not a console: on a herbarium sheet a mark means something because of where it sits and what it is drawn from, so the marks here are shapes cut from the same tokens as everything else.

Use a mark when the mark is the meaning — health, confidence, position, an unloaded region. Use words when the meaning is an instruction. A mark never replaces the word next to it; it stands beside it so the state can be found by glance and confirmed by reading.

The rule in one line

Every mark has a text equivalent in the same component. If you cannot write that text, you do not have a mark — you have decoration, and it does not ship.

The mark inventory

These are all of them. Each belongs to a component, is drawn by that component's CSS, and is documented in full on that component's page.

Every colour in that table is a semantic role. Never reach past it to a primitive — the reasoning is on Colors.

The direction arrow

The one glyph in the system is the arrow an edge draws after itself. It is a character in CSS, not an image, and the component chooses it: a forward edge draws →, an edge back to where you came from draws ↖, and under a right-to-left locale the forward arrow flips to ← on its own.

Because of that, you must never type an arrow into your own copy. Write the destination; the edge draws the direction.

<!-- correct: the edge draws its own arrow, in the reader's own direction -->
<a class="hbm-nav" href="#">Monstera</a>

<!-- wrong: a hard-coded arrow points the wrong way in Arabic -->
<a class="hbm-nav" href="#">Monstera →</a>

The full locale rules are on RTL & locale.

Icon-only actions

An action may drop to a mark alone when space is genuinely short and the same action is spelled out somewhere on the same view. Use .hbm-act--icon, put a single character inside it, and give it a real name with .hbm-visually-hidden.

An icon-only control is still an action, so it still obeys the action rules on Actions: it mutates something, it never navigates, and it never borrows the form of an edge.

Sizing, colour and motion

Marks are sized from the space scale, not from a font size, so they hold their proportion when a reader enlarges text. The leaf is --hbm-space-3 square, a rung is --hbm-space-3 by --hbm-space-2, the dot is --hbm-space-2, the you-are-here marker is --hbm-space-4. Those values live in the components; do not restate them on a page.

Three constraints apply to every mark:

  • No mark carries its own colour. It takes a semantic role, or it takes currentColor from the text around it, so both themes are correct without a second definition.
  • No mark animates. Marks are drawn, not performed — nothing here spins, pulses or pops. The only moving mark is the you-are-here marker, and it travels with --hbm-motion-travel because it is reporting a real change of position.
  • No mark is decorative. If it does not report state, it is not in the system.

Under prefers-reduced-motion the motion durations collapse to near zero, so the marker updates without a journey and every mark stays drawn and readable. Nothing disappears in reduced motion.

Accessibility

The marks are the part of this system most likely to fail a reader, so they carry the strictest rules.

Never colour alone

Health and confidence both change colour between states, and colour alone is not a reading. That is why .hbm-health and .hbm-confidence both include their label inside the component: the leaf and the rungs are a second, faster channel on top of the word, never a substitute for it. A reader with a colour-vision difference gets the state from the text; a reader in a hurry gets it from the mark.

Naming and announcement

Marks are empty <span> elements with no text, so a screen reader passes over them silently and announces the label instead — "Needs attention", not "image, yellow". Keep it that way: never put aria-label on a mark, and never add role="img" to one.

An icon-only action is the exception, because there is no visible word to read. Give it a .hbm-visually-hidden name that says the object as well as the verb — "Add a plant to my garden", not "Add" — so the announcement makes sense out of context.

Contrast and target size

Every mark colour is a semantic role that is contrast-checked against its own surface in both paper and dusk, so a mark stays legible in either theme without a page-level override. Marks are never interactive on their own; when a mark sits inside a control, the control provides the hit target and the focus ring — .hbm-act--icon is a full-size button, not a bare glyph.

Keyboard

Nothing on this page introduces a new keyboard path. A mark is not focusable and never appears in the tab order. An icon-only action is a real <button>: it is reached by Tab, fired by Enter or Space, and shows the same focus outline as any other action.

Usage guidance

Do
Needs attention

Keep the mark and its word together, so the state can be seen at a glance and confirmed by reading.

Don't

Strip the word and leave the mark to carry the state alone — a reader who cannot separate the colours learns nothing.

Do
Recent scans

Let the dot take its colour from the badge it sits in, so one mark serves every tone without a new class.

Don't
Recent scans

Borrow the health leaf for something that is not a health reading — the mark then means two things and reports neither.

If you need a mark that is not here

Write the page or the screen without it and raise the gap. A new mark is a change to the system, and this file is frozen for v1.0.0 — see the principles for why the vocabulary stays small.
